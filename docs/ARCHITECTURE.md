# Архітектура системи

## Fullstack Architecture

### Backend (FastAPI)
Обробка важких обчислень, Sensor Fusion та інтерполяція. Виконує парсинг MAVLink логів, конвертацію координат, математичну оптимізацію траєкторії та розрахунок кінематичних метрик. Забезпечує REST API для фронтенду з асинхронною обробкою запитів.

### Frontend (React/Three.js)
3D-рендерінг траєкторії через Three.js з OrbitControls. Реалізує динамічне колорування маршруту залежно від швидкості (speed) через градієнтну схему та часу (time_s) для анімації польоту. Інтерактивна навігація по точках траєкторії з відображенням метрик у реальному часі.

## Data Processing Pipeline

### Parsing
Робота з pymavlink для витягування POS, GPS, IMU, ATT повідомлень. Обов'язково обробляються повідомлення GPA для отримання HAcc (горизонтальна похибка) та SAcc (похибка швидкості) для оцінки якості сигналу та динамічної фільтрації невалідних GPS-даних.

### ENU Conversion
Перехід WGS-84 → ENU з фіксацією точки зльоту (динамічний нуль). Конвертація градусів в метри з урахуванням кривизни Землі для локальної навігації.

## Математичне обґрунтування (Критерії ТЗ)

### Haversine Formula
Розрахунок дистанції через сферичну геометрію (обов'язкова вимога ТЗ). Використовується для точного обчислення пройденої відстані на сферичній поверхні Землі з урахуванням радіуса планети.

### Trapezoidal Rule
Інтегрування прискорень для отримання швидкості (обов'язкова вимога ТЗ). Метод трапецій забезпечує оптимальний баланс точності та продуктивності для зашумлених даних IMU, мінімізуючи похибку дискретизації.

### Orientation
Використання кватерніонів (scipy.spatial.transform.Rotation) для уникнення 'gimbal lock' при складних просторових маневрах БПЛА. Забезпечує неперервність обертання при довільних кутах атаки.

### Cubic Splines
Використання сплайнів для усунення 'сходинок' (різких корекційних стрибків GPS) та забезпечення неперервності похідних (плавність швидкості). Генерує фізично коректну траєкторію з природною кривизною.

## Продуктивність

Використання NumPy для векторних операцій та матричних обчислень. Асинхронність FastAPI для паралельної обробки запитів. Streaming обробка даних для мінімізації споживання пам'яті. WebGL рендеринг через Three.js для високопродуктивної 3D-візуалізації.

## API Contract

### Ендпоінт /api/v1/process-log

**Вхід:** .BIN файл з MAVLink логом
**Вихід:** JSON з масивом точок та розрахованими метриками

Структура відповіді:
- data: масив точок траєкторії (x, y, z, lat, lon, alt_abs, speed, time_s)
- analysis: блок з метриками (_m, _ms, _mss, _s)
- meta: службова інформація про обробку
