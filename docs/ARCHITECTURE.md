# Технічна Архітектура

## Конвеєр Даних

### 1. Конвеєр Обробки Логів
```
.BIN → pymavlink → WGS-84 → ENU → Згладжування Сплайнами → 3D Візуалізація
```

**Етапи:**
- **Бінарний Парсинг**: Файли логів Ardupilot `.BIN` декодуються через pymavlink
- **Трансформація Координат**: WGS-84 (широта/довгота/висота) в ENU (Схід-Північ-Вгору) локальну тангенціальну площину
- **Цілісність Сигналу**: Оцінка точності GPS за допомогою повідомлень GPA (параметри HAcc/SAcc)
- **Оптимізація Траєкторії**: Інтерполяція кубічними сплайнами для гладкого рендерингу

### 2. Валідація GPS Сигналу
- **HAcc (Горизонтальна Точність)**: RMS радіус помилки в метрах
- **SAcc (Точність Швидкості)**: Невизначеність оцінки швидкості
- **Фільтрація**: Точки з HAcc > 5м позначаються як низькоінтегритетні

## Алгоритмічна Основа

### 1. Розрахунок Дистанції: Формула Гаверсайна
```python
a = sin²(Δφ/2) + cos(φ1) * cos(φ2) * sin²(Δλ/2)
c = 2 * atan2(√a, √(1-a))
distance = R * c
```
- **Призначення**: Дистанція по великому колу на еліпсоїді WGS-84
- **Точність**: <1% помилки для дистанцій <1000км

### 2. Інтеграція Швидкості: Метод Трапецій
```python
velocity = ∫acceleration dt ≈ Σ[(a_i + a_{i+1})/2 * Δt]
```
- **Застосування**: Перетворення прискорення IMU в швидкість
- **Корекція Помилок**: Оновлення швидкості GPS для компенсації дрейфу

### 3. Обробка Орієнтації: Кватерніони
```python
q_new = q_current ⊗ [0, ω_x, ω_y, ω_z] * dt/2
```
- **Перевага**: Уникає gimbal lock, сингулярностей
- **Обчислення**: 4D представлення обертання проти 3D кутів Ейлера

### 4. Згладжування Траєкторії: Кубічні Сплайни
```python
S''(x_i) = 0 (природні граничні умови)
S'(x_i⁺) = S'(x_i⁻) (C1 неперервність)
```
- **Фізична Неперервність**: Забезпечує гладку першу похідну (швидкість)
- **Інтерполяція**: Обробка пропущених GPS пакетів з математичною неперервністю

## Архітектура Sensor Fusion

### 1. Проблема Подвійної Інтеграції IMU
- **Інтеграція Прискорення**: ∫∫a dt² → позиція
- **Накопичення Дрейфу**: Помилка зростає як O(dt²)
- **Посилення Шуму**: Білий шум → випадкове блукання → дрейф позиції

### 2. Механізм GPS Корекції
```python
position_fused = (1-α) * position_imu + α * position_gps
```
- **Фільтр Калмана**: Оцінка стану з оновленнями вимірювань
- **Адаптивна Вага**: α динамічно коригується на основі метрик точності GPS
- **Компенсація Дрейфу**: Періодичні оновлення абсолютної позиції

```javascript
color = interpolate(velocity, min_v, max_v, color_scale)
```

- **Візуалізація**: Кольорування траєкторії залежно від швидкості

- **Instanced Rendering**: Пакетна обробка викликів малювання для точок траєкторії

## Математичні Моделі

### 1. Трансформація Системи Координат
```python
ENU = R * (LLA - LLA_ref)
R = rotation_matrix(lat_ref, lon_ref)
```

### 2. Поширення Помилок
```python
σ_position² = σ_imu² + σ_gps² * (1-α)²
```

### 3. Граничні Умови Сплайнів
```python
S''(x_0) = S''(x_n) = 0  # Природні сплайни
S'(x_i⁻) = S'(x_i⁺)      # Неперервність швидкості
```

## Метрики Продуктивності

- **Швидкість Обробки**: 1000Гц IMU, 10Гц GPS ф'южн
- **Використання Пам'яті**: <500МБ для логів 1-годинного польоту
- **Рендеринг FPS**: 60Гц при 1080p з 100К точок траєкторії
- **Точність**: Помилка позиції <2м при GPS HAcc <3м
